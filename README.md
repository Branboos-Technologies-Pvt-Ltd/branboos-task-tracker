# BranBoos Task Tracker

An internal, shared, Jira-lite Kanban board for **BranBoos Technologies Pvt. Ltd.** — self-hosted, opinionated, small-team-first.

Live: **https://tasks.branboos.com**
Repo: **https://github.com/Branboos-Technologies-Pvt-Ltd/branboos-task-tracker**

> ⚠️ **Note on brand casing:** always spell it `BranBoos` (two capital B's) in display strings. The lowercase `branboos` only appears in URL slugs and identifiers where casing doesn't matter.

---

## Overview

A workspace-scoped Kanban tool. All members of the BranBoos workspace see the same boards, lists, and cards. There is deliberately no per-board permission — small teams benefit from radical transparency. Every card gets a Jira-style key (`BRAN-1`, `BRAN-2`, ...) auto-assigned on creation.

Feature summary:

- Boards → Lists → Cards, with drag-and-drop between lists (via `@dnd-kit`)
- Card fields: title, description, component tag, priority, start/due dates, assignee
- Card key display (`BRAN-N`), unique per workspace
- Board search, sort (recent/A→Z/newly created), pagination (12 per page)
- Sidebar with recent-boards quick-nav, collapsible with persistent state
- Filter bar on boards: search, assignee, priority, "My cards"
- Members roster, My Cards view
- Password sign-in + email magic-link fallback + password reset
- User profile: full name captured at signup; existing users are prompted via a banner

## Environment variables

Both `.env` (used by Prisma CLI) and `.env.local` (used by Next.js at runtime) need to be filled in. In production, they live in Netlify's environment variables UI.

| Variable | Scope | Purpose |
|---|---|---|
| `DATABASE_URL` | server | Supabase **pooled** URL (port `6543`, Supavisor). Used by Prisma at runtime. Must include `?pgbouncer=true`. |
| `DIRECT_URL` | server | Supabase **direct** URL (port `5432`). Used by `prisma migrate` and `prisma db execute` from the local machine. |
| `NEXT_PUBLIC_SUPABASE_URL` | client + server | e.g. `https://<project-ref>.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | client + server | Public anon key (safe to expose — RLS protects data). |
| `NEXT_PUBLIC_SITE_URL` | build-time | Canonical origin the app should redirect to. **Must not have a trailing slash.** In prod: `https://tasks.branboos.com`. Locally: `http://localhost:3000`. |

**In Netlify:** every variable must have scope = **All scopes** (not just Runtime). `NEXT_PUBLIC_*` are baked in at build time, so change → **Trigger deploy** to pick up.

## Data model

Prisma models (all in `public` schema, with `@@map` overriding to lowercase-snake table names):

- **Profile** (`profiles`) — mirrors `auth.users` row-for-row via signup trigger; holds `full_name`, `avatar_url`. FK `id → auth.users(id)` maintained via SQL, not Prisma.
- **Workspace** (`workspaces`) — one per company. Has `name`, `slug`, `prefix` (used for card keys).
- **WorkspaceMember** (`workspace_members`) — many-to-many between profiles and workspaces with a role enum (`owner` / `admin` / `member`).
- **WorkspaceCardSequence** (`workspace_card_sequences`) — one row per workspace, tracks `last_number` for card key generation. Incremented atomically in a transaction on card creation.
- **Board** (`boards`) — belongs to a workspace. Has color/description/archivedAt for future use.
- **List** (`lists`) — belongs to a board. Has `position` (float, fractional indexing).
- **Card** (`cards`) — belongs to a list AND a workspace (denormalized for fast lookup + card-key uniqueness). Fields: `title`, `description`, `component`, `priority`, `start_date`, `due_date`, `assignee_id`, `created_by`, `position`, `number`.
- **Comment** (`comments`) — schema exists, UI not built yet.

**Position values (List.position, Card.position) are floats used for fractional indexing** — drag to a new spot between neighbours = new position is the average of the two. Avoids renumbering siblings.

**Cross-schema link:** `profiles.id → auth.users.id` is a FK added via `prisma/sql/001_auth_bridge.sql`. Prisma is intentionally kept unaware of the `auth` schema; adding `multiSchema` to the Prisma datasource makes it want to reset all of Supabase's auth tables as "drift". See gotcha section.

## Authentication

Three flows built with Supabase Auth + `@supabase/ssr`:

### 1. Password sign-in (default)
Form submits to `signInWithPassword` server action → Supabase creates a session cookie → redirect to `/app`. Fast, browser-autofillable.

### 2. Magic-link OTP (fallback)
User clicks "Trouble signing in? Email me a code instead". Server action calls `signInWithOtp`. User receives email with both a click-link AND a numeric code (6-10 digits — Supabase default recently changed to 8). Either path completes the sign-in.

### 3. Sign-up
Sign-Up tab collects **name + email + password**. Server action calls `signUp` with `options.data.full_name = ...`. Supabase creates the user (pending email confirmation) and sends confirmation email. On click, user is signed in and redirected to `/app`. The `handle_new_user` trigger (in `001_auth_bridge.sql`) automatically creates their `profiles` row with the full name from `user_metadata`.

### Password reset
"Forgot password?" → `resetPasswordForEmail` with `redirectTo: /auth/callback?next=/auth/reset-password`. User clicks email link → callback exchanges code for a recovery session → `/auth/reset-password` shows the new-password form → `updateUser({password})` → redirect to `/app`.

### Auth trigger (SQL)
`handle_new_user()` in `001_auth_bridge.sql` runs `AFTER INSERT ON auth.users` and:
1. Inserts a matching `profiles` row using `raw_user_meta_data->>'full_name'`
2. Auto-joins the user to the Branboos workspace as `member` (first user is `owner` by seed)

### Middleware
`src/middleware.ts` (via `updateSession` in `lib/supabase/middleware.ts`) refreshes the auth cookie on every request and redirects to `/login` if trying to access a `/app/*` route without a session.

## Database migrations — how we manage them

**We do NOT run `prisma migrate dev` after the initial migration.** Reason: Prisma sees Supabase's `auth` schema as drift and wants to reset it (which would nuke all users).

Workflow for schema changes:

1. Edit `prisma/schema.prisma` to reflect the new state
2. Write a hand-crafted SQL file in `prisma/sql/NNN_description.sql` — must be idempotent (`IF NOT EXISTS`, `OR REPLACE`, etc.)
3. Apply against Supabase: `npx prisma db execute --file .\prisma\sql\NNN_description.sql`
4. Regenerate the client: `npx prisma generate`
5. Commit both the schema + the SQL file

Numbered SQL files so far: 001 (auth bridge), 002 (seed workspace), 003 (add component + start_date), 004 (card key), 005 (enable RLS), 006 (un-force RLS), 007 (rebrand workspace name).

### Row-Level Security

All `public.*` tables have RLS enabled with **no policies** — default deny for `anon` and `authenticated` roles. Prisma connects as the `postgres` role which bypasses RLS, so app queries continue to work. The point is to shut the back door: the anon key (public) cannot be used to read/write these tables via PostgREST.

FORCE RLS is intentionally NOT set on `profiles`, `workspace_members`, `cards`, `comments` because the `handle_new_user` trigger (SECURITY DEFINER) needs to insert into `profiles` and `workspace_members` on signup.

## Non-obvious gotchas

Things a fresh contributor (or AI agent) will trip on:

### Prisma
1. **Lazy PrismaClient.** `src/lib/prisma.ts` uses a Proxy so `prisma` can be imported without triggering DB connection. Required because Netlify's build imports server modules to check pre-rendering; if `DATABASE_URL` is missing at build, an eager instantiation would crash.
2. **Prisma 7 requires driver adapter.** `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })`. The bare `new PrismaClient()` no longer works.
3. **Generated client is gitignored** at `src/generated/prisma/`. Regenerated on `npm install` via `postinstall`.
4. **Don't add `multiSchema`.** It causes Prisma to see Supabase's entire `auth` schema as drift and want to reset the DB.

### Auth / Supabase
5. **PKCE flow requires same-browser click.** The magic-link code exchange needs the `code_verifier` cookie that was set when the form was submitted. Click the link from the same browser you submitted from — or use the 6-10 digit OTP fallback (works cross-device).
6. **Canonical origin in /auth/callback.** Redirects use `NEXT_PUBLIC_SITE_URL` (not `request.nextUrl.origin`) to avoid Netlify's internal alias URLs breaking cookie scoping.
7. **`NEXT_PUBLIC_SITE_URL` must not end in `/`.** Otherwise `emailRedirectTo` becomes `.../auth/callback` with a double slash, fails to match Supabase allow-list, falls back to Site URL.
8. **Trigger runs SECURITY DEFINER.** `handle_new_user` in `001_auth_bridge.sql` inserts into `public.profiles` as the function owner. RLS is enabled but NOT forced on `profiles`, so this works. Do not add `FORCE ROW LEVEL SECURITY` to profiles.
9. **OTP length is 8 digits by default** in newer Supabase projects (used to be 6). Our code accepts 6-10 via regex.

### Next.js
10. **Middleware file is deprecated** in Next 16 in favor of `proxy.ts`. Non-blocking build warning; safe to ignore or rename later.
11. **Root layout metadata title** uses a template — individual pages can override.
12. **Server actions in `useTransition`** should not be called inside a `setState` updater — React will throw "Cannot call startTransition while rendering." All drag-end logic in `board-view.tsx` computes new state first, then calls `setLists` and `startTransition` at the top level.

### UI
13. **shadcn Button uses base-ui** — no `asChild` prop. Wrap the button inside a Link or apply `buttonVariants(...)` classes to the Link directly.
14. **Prefer `lucide-react` icons.** Consistent style, well-maintained. Avoid mixing icon libraries.
15. **Column theme + component color are deterministic hashes** of the column/component name. So "Frontend" always gets the same color across boards and sessions.
16. **BranBoos wordmark uses two capital B's.** Fix any occurrence of `Branboos` (single capital) in display text.

### Deployment
17. **Netlify builds cost minutes.** ~2-3 minutes per build, 300/month free. Batch commits before pushing.
18. **Env vars must have "All scopes" set** in Netlify (not just Runtime). Build-time reads `NEXT_PUBLIC_*` from build scope.
19. **After changing a `NEXT_PUBLIC_*` env var, redeploy manually** — they're baked in at build time.

## How to make common changes

### Add a new schema field
1. Edit `prisma/schema.prisma` to add the field on the appropriate model
2. Write `prisma/sql/NNN_add_field.sql`:
   ```sql
   ALTER TABLE public.table_name
     ADD COLUMN IF NOT EXISTS field_name field_type;
   ```
3. `npx prisma db execute --file .\prisma\sql\NNN_add_field.sql`
4. `npx prisma generate`
5. Use in code
6. Commit schema + SQL + code changes

### Add a shadcn component
```powershell
npx --yes shadcn@latest add <component-name> -y
```
Verify no dependency on Node-only modules (`pg`, `fs`) leaks into client bundles. Keep client-safe utilities in `.ts` (no `import from '@/lib/prisma'`); put server queries in `.server.ts` files.

### Add a new page under /app
Create `src/app/app/<route>/page.tsx`. It automatically inherits the sidebar + top-header layout. Use `requireProfile()` at the top for user + workspace context. If it needs Prisma queries, import them directly — the layout already ensures the user is authenticated.

### Add a new auth trigger or backfill
Write a new SQL file (`prisma/sql/NNN_...`), execute it, commit.

- SQL files are numbered + idempotent
- Types shared between server and client live in `types.ts` files (no Prisma imports)

Before committing:
1. `npm run build` locally — catches typing / rendering errors that dev mode hides
2. Verify no secrets in the diff (`git diff --staged | grep -i "key\|password\|secret"`)
3. Keep commits focused and small so pushes stay batchable

Before pushing to prod (Netlify auto-deploys on push):
1. `git log origin/main..HEAD --oneline` to see the queue
2. Only push when the batch is testable / worth spending a Netlify build minute
